# CLOVA General 파서 인식률 기준선

측정일: 2026-09-18
대상: `supabase/functions/ocr/clova-general.ts` 의 `extract()` (이번 측정에서 파서는 한 줄도 고치지 않았다)
채점기: `node scripts/ocr-bench/score.mjs`
표본: 한국 영수증 카탈로그 38장 (`.local/receipt-corpus/catalog.json`, 저장소 밖 · 읽기 전용)

## 재현 방법

```sh
# 카탈로그를 .local/receipt-corpus/ 에 두거나 경로를 환경 변수로 준다.
RECEIPT_CORPUS_DIR=../wolfeel/.local/receipt-corpus node scripts/ocr-bench/score.mjs
node scripts/ocr-bench/score.mjs --json   # 회귀 비교용
```

카탈로그가 없으면 이유를 적고 exit 2 로 끝난다. CLOVA·Gemini API 는 호출하지 않는다.

## 기준선 (2026-09-18)

```
카탈로그: .local\receipt-corpus\catalog.json  (38장 중 33장 채점, 5장 제외)

  제외 029: truth 가 네 필드 모두 null(영수증에 원래 없음)

merchant           4/15   26.7%         0             9           2

amount            17/24   70.8%         0             4           3

```

**전체 68.7% (46/67).** 목표 99% 까지 21건이 남았다.

분모는 `truth` 가 null 이 아닌 필드만 센다. 마스킹·저해상도로 사람도 못 읽어 정답이 null 인
필드는 "파서가 못 읽은 것"과 섞이면 숫자가 거짓말을 하므로 분모에서 뺐다. 그래서 분모가
필드마다 다르다(가맹점 15, 일시 23, 금액 24, 카드번호 5).

`paidAt` 의 부분 정답 1건(059)은 정답으로 세지 않았다. 날짜는 맞고 시각만 `00:00:00` 으로
채운 경우다.

### 채점에 쓴 장수

38장 중 **33장**을 채점했다. 뺀 5장(004, 028, 029, 076, 088)은 `truth` 네 필드가 모두 null,
즉 마스킹·화질 문제로 육안으로도 정답을 못 읽은 항목이라 분모에 기여할 필드가 하나도 없다.
`visible_lines` 가 빈 항목은 없었다.

보고서 5위 "유효기간 슬래시가 카드번호를 끊음"(064, 065)도 `truth.cardNumber` 가 null 이라
이번 채점에 들어오지 않았다. 예측이 틀렸다기보다 **표본에서 채점 가능한 필드가 없었다.**

### 조용히 틀린 것 vs 표시된 채 틀린 것

21건 중 **6건은 `weak` 표시 없이 조용히 틀렸다**(002, 003, 077, 081, 091-가맹점, 060).
나머지 15건은 `weak` 에 이름이 올라 Gemini 보완·사용자 확인으로 갈 기회가 있다.
조용한 오답이 심각도가 높다. 특히:

- 002·003 금액(100,000 → 90,909): 다수결이 `keyed: true` 로 확신까지 실었다.
- 077·091 가맹점(`"가게보기"`): 그럴듯한 한국어라 사용자가 오탈자로 오해하기 쉽다.
- 060 카드번호: `cardNumber` 는 설계상 `weak` 에 넣지 않으므로 항상 조용하다.

## 합성 입력의 한계

이 숫자는 **합성 좌표**로 낸 것이다. 채점기는 카탈로그의 `visible_lines`(사람이 눈으로 읽은
글자 줄)를 `linesToFields()` 로 격자 좌표에 얹어 CLOVA 응답 모양을 만든다. 줄 높이 26,
줄 간격 30, 고정폭 13px, 넓은 공백(2칸 이상)은 좌우 단으로 크게 벌린다. 따라서 **검증되는
것은 파서의 규칙**(라벨 매칭, 정규식, 금액 다수결, 좌우 단 분리)뿐이고, **실제 OCR 이 만드는
잡음은 하나도 재현하지 못한다** — 기울어진 사각형, 글자 오인식, `lineBreak` 묶음이 위→아래
순서가 아니게 뒤섞여 나오는 현상, 들쭉날쭉한 줄 간격은 전부 빠져 있다. 게다가 `visible_lines`
자체가 사람이 잘 읽어 정리한 결과라 OCR 의 첫 단계 실패는 애초에 표본에 없다. 줄 재구성의
진짜 기준은 실제 응답 픽스처 3장(receipt-1/2/3, `supabase/functions/ocr/clova-general.fixtures.ts`)
이고 이 합성 입력은 그 위에 얹는 보조 자다. **여기서 99% 가 나와도 실제 인식률이 99% 라는
뜻이 아니다. 규칙 회귀를 잡는 용도로만 써라.**
