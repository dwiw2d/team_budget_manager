# Supabase 일시정지 막기 (keepalive)

## 1. 왜 필요한가

이 프로젝트의 Supabase 는 무료 요금제다. 무료 프로젝트는 **7일간 데이터베이스 활동이 낮으면
자동으로 일시정지**된다. 기준은 "지난 한 주 동안 하루에 몇 건의 요청" 이다
(https://supabase.com/docs/guides/platform/free-project-pausing).
일시정지되면 앱은 그냥 붙지 않는다. 데이터가 사라지지는 않지만 사람이 대시보드에서 손으로 깨워야 한다.

내장 `pg_cron` 으로는 못 푼다. **데이터베이스 안에서** 도는 작업이라 바깥에서 들어온 요청으로 세어지지 않는다.
요청이 바깥에서 와야 한다.

여기에 제약이 하나 더 붙는다. 공개 저장소의 GitHub Actions 예약 작업은 **60일간 새 커밋이 없으면 꺼진다**.
우리가 프로젝트를 한동안 손대지 않을 때, 즉 이 장치가 정확히 필요한 순간에 꺼진다는 뜻이다.
그래서 같은 워크플로가 저장소에도 커밋을 하나 남겨 이 타이머를 매일 되돌린다.

## 2. 무엇을 하는가

`.github/workflows/keepalive.yml` 이 **매일 UTC 03:17(한국 시간 낮 12시 17분)** 에 두 가지를 한다.
정시(`0 * * * *`)를 피한 것은 그 시각에 몰리는 실행 지연을 피하려는 것이다.

1. **Supabase 핑** — `POST {URL}/rest/v1/rpc/ping` 를 anon 키로 부른다.
   `public.ping()`(마이그레이션 `0007_keepalive.sql`)은 `keepalive` 표의 `last_ping` 을 `now()` 로
   **갱신하고** 그 값을 돌려준다. 읽기가 아니라 쓰기여야 활동으로 확실히 잡힌다.
   응답이 200 이 아니거나 본문에 시각이 없으면 **작업을 실패시킨다**. GitHub 이 실패 메일을 보내므로
   조용히 멈춘 채 7일이 흐르는 일을 막는다.
2. **저장소 활동 남기기** — `keepalive` 라는 별도 브랜치에 시각만 담은 `keepalive.txt` 하나를
   고아 커밋으로 덮어써 강제 푸시한다. `main` 이력이 더러워지지 않고, 배포 워크플로(`deploy.yml`)는
   `main` 푸시만 보므로 다시 돌지 않는다. 이력도 매번 커밋 한 개로 덮여 쌓이지 않는다.
   이 단계는 실패해도 작업 전체를 실패시키지 않는다(핑은 이미 성공했으므로). 대신 로그에 남는다.

표에는 RLS 를 켜 두고 정책은 두지 않았다. 아무도 표에 직접 손대지 않고 `ping()` 으로만 들어온다.
`ping()` 실행 권한은 `anon` 과 `authenticated` 에 열려 있다. 하는 일이 시각 갱신뿐이라 노출해도 안전하다.

저장소 variables 의 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` 를 그대로 쓴다. 따로 등록할 비밀 값은 없다.

## 3. 잘 도는지 확인하기

- **Actions 탭** → 왼쪽 `keepalive` → 최근 실행이 하루 안쪽이고 초록인지 본다.
  예약 실행은 몇 분에서 몇십 분 늦을 수 있다. 그 정도 지연은 정상이다.
- **마지막 핑 시각** — Supabase 대시보드의 SQL Editor 에서:

  ```sql
  select last_ping from keepalive;
  ```

  오늘 날짜면 정상이다. 며칠 전이면 핑이 멈춘 것이다.
- **커밋 쪽** — `keepalive` 브랜치의 마지막 커밋 날짜가 오늘이면 60일 타이머도 되돌아가고 있다.

## 4. 멈췄을 때

| 증상 | 대처 |
| --- | --- |
| 실행이 빨간색 (핑 실패) | 로그의 HTTP 코드와 응답을 본다. 404 면 `0007` 마이그레이션이 클라우드에 안 올라갔거나 권한이 빠진 것이다. |
| 실행 기록이 며칠째 없음 | 60일 자동 중지에 걸렸을 수 있다. Actions 탭에서 워크플로를 **Enable** 하고 **Run workflow** 로 한 번 돌린다. |
| 앱이 아예 안 붙음 | 이미 일시정지된 것이다. Supabase 대시보드에서 **Resume** 를 누른다. 깨어나는 데 몇 분 걸린다. 그다음 위의 수동 실행으로 핑이 다시 도는지 확인한다. |

수동 실행은 Actions 탭 → `keepalive` → **Run workflow** 버튼이다. 예약을 기다릴 필요 없이 바로 확인할 수 있다.
